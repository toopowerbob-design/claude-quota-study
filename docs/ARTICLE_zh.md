# 每月 200 美元的 Claude 訂閱，一週額度到底值多少 API 美元？

（研究文章。數字取自庫裡的 `RESULTS.md`、`data/cells.csv` 與 `bin/compare_models.py` 的輸出（跨模型的倍數）。量測期間是 2026-11-17 15:50 到 2026-11-18 01:45（台灣時間 UTC+8；民國 115 年 11 月 17 日至 18 日），約 10 小時，都在同一個每週額度視窗內，結束時週額度讀數 51%。文中凡是「每 1% 多少美元」都是範圍，與 `RESULTS.md` 一樣取到小數一位（四捨五入；只量到下限的那一格往下取）；倍數也取到小數一位；外推的金額取到十位或百位，都是近似值。）

## 這個問題為什麼難回答

Claude Code 的訂閱方案不告訴你「還剩多少 token」，只給你一個百分比：這一週用了百分之幾，而且只有整數。API 則是另一套算法：輸入、輸出、寫入快取、讀取快取各有牌價，不同模型價差數倍。

兩套算法之間怎麼換算，官方沒有說明。於是有兩個一直沒人講清楚的問題：

1. 每月 200 美元的方案，一週的額度如果改走 API，照牌價要付多少錢？
2. 用貴的模型扣得比較快，這大家都知道。但扣額度的比例，等於 API 的價差嗎？

我手上剛好有一個全新、用量 0% 的帳號，訂的是每月 200 美元的方案（介面顯示為 Ultra，即原本的 Max 20x），就拿它來量。

## 怎麼量

**兩條互相獨立的資料線。**

- 額度讀數：設定頁「用量」顯示的那個百分比。程式每隔大約兩分鐘讀一次，不呼叫模型、不花額度。
- 用量帳本：Claude Code 在本機留下的對話紀錄檔裡，每一次模型呼叫都記了輸入、輸出、快取寫入、快取讀取各多少 token。把這些數字乘上官方 API 牌價，就是「同樣的用量走 API 要付多少美元」，以下叫「API 等值」。

事後用時間把兩條線對起來：額度每跳 1%，當下累計了多少美元。

**一次只讓一種模型、做一種工作。** 我設計了三種固定的工作，交給子任務去跑：

| 工作 | 內容 | 成本落在哪 |
|---|---|---|
| 讀檔 | 讀 12 個固定大小的文字檔（約 40 萬 token） | 大部分是快取寫入（八到九成） |
| 寫長文 | 寫好幾章、每章九千字以上的長文 | 輸出占四到七成，其餘多是快取寫入 |
| 反覆讀快取 | 先讀同樣的檔，再連續做 200 到 250 次小動作，每次都重讀整份上下文 | 大部分是快取讀取（七成半到九成半，看模型） |

檔案內容是固定種子產生的無意義英文單字，所以每份工作的 token 數幾乎一樣。跑了四個模型：Haiku 5.5、Sonnet 5.5、Opus 5.5、Fable 5.2。Haiku 沒有跑寫長文，反覆讀快取也只量到下限。

**讀數只有整數，所以只報範圍。** 我不做「除一除得到一個數字」這種事。每一格實驗裡，找出第一次和最後一次讀數跳動，看這兩次之間帳本累計了多少美元，除以跳了幾個百分點，就夾出上下限。規則有三條：跳動前後的兩筆讀數都要落在這一格裡才算；容許本機紀錄檔比官方計量晚 60 秒；主持對話（發動並記錄這次實驗的那個 Claude Code 對話，用的是 Fable 5.2）自己也在用額度，它的用量只從上限那一頭扣掉。

另外用線性規劃把所有讀數當成限制條件，直接檢驗某個假設會不會跟讀數矛盾。官方沒說百分比怎麼取整，也沒辦法確定起跑那一刻的真值，所以這兩件事都當成未知數，三種取整方式各算一次。

**重複，而且反著順序重複。** Sonnet 的三種工作下午依序跑一次，晚上反過來再跑一次。

**找人挑錯。** 整個過程請 AI 審查員（另外開的獨立模型對話）審了四輪，不是真人同行審查：每輪由幾個審查員各自從 GitHub 把整個庫重新抓下來實跑，再由另一個審查員逐項找反證、做最後把關。第一、二輪是 3 個 Sonnet 5.5 加 1 個 Opus 5.5（記在 `PROTOCOL.md` 與 `data/events.jsonl`），各確認 26 個問題，包括我自己講太滿的結論。審查紀錄沒有放進這個庫，所以這個數字外人沒辦法核對。第三輪之後分析方法才定版；最後一輪，審查員不用我的程式，自己從庫裡的原始資料把表上每一個範圍重算一遍，對得上（審查時的資料比公開版長，各格範圍相同，`fit` 的數字在公開版重新算過）。最後把關的審查員另外擋下三個小地方（一句牌價的說法、一條沒寫進文件的規則、一欄資料與文件不一致），修掉之後才公開。

## 總帳

從 0% 到 51%，大約 10 個小時。四個模型合計的 API 等值約 936 美元：Sonnet 約 330、Opus 約 325、Fable 約 183、Haiku 約 98。

每月 200 美元，攤到一週大約 46 美元。也就是說，一半的週額度，照牌價算是九百多美元。

## 結果一：不是把 API 帳單乘上一個固定倍數

最直覺的猜測是「訂閱額度就是 API 帳單的某個倍數」。這個猜測與讀數矛盾。

- 假設所有模型共用同一個倍數：起跑值未知，預設的時間容許下，三種取整方式合計要容許 8.02 到 8.41 個百分點的誤差才對得上；把時間誤差放到很寬（讀數延遲十分鐘、紀錄檔落後五分鐘），無條件捨去那一種還是要 7.93 個百分點。
- 放寬成每個模型各有一個倍數：起跑值未知，預設的時間容許下，三種取整方式合計要容許 0.72 到 0.77 個百分點；把時間誤差放到很寬，也還要約 0.54 個百分點才對得上（`RESULTS.md` 印的是無條件捨去；其餘兩種取整方式重跑是 0.54 與 0.55，指令是 `.venv/bin/python bin/analyze.py fit --lag 600 --lead 300 --slack 0.1 --rounding round`（四捨五入，得 0.54），同樣的參數改成 `--rounding ceil` 是無條件進位（得 0.55））。這些重跑會在 `data/fit/` 底下另外寫出檔案，不屬於公布的結果，可以刪除。
- 再放寬成每個模型的每一類 token 各有一個換算：預設的時間容許下，三種取整方式合計還差 0.21 到 0.39 個百分點；把時間誤差放寬之後，可以與全部讀數相容。

這三條的強度不一樣。「所有模型共用同一個倍數」被明確推翻，差了約 8 個百分點。「每個模型各有一個倍數」只是不太對得上，不算明確推翻：差 0.72 個百分點（時間誤差放很寬是 0.54），和資料本來就對不上的約 0.2 個百分點（預設時間容許值下，最寬鬆的假設三也還差 0.21 到 0.39）相去不遠。更直接的證據在下一節：同一個模型做不同的工作，每 1% 對應的美元範圍互不重疊（Opus 反覆讀快取 30.4 到 50.8，寫長文 18.8 到 25.0），這用不到線性規劃就看得出來。合起來的讀法是：訂閱和 API 用的不是同一張價目表，而且同一個模型裡不同種類的 token 也不照牌價的比例扣。

## 結果二：扣 1% 週額度，可以用掉多少美元

下表是「扣 1% 每週額度，對應多少美元的 API 等值用量」。數字越大，代表同樣一格額度換到的用量越多。

| 工作 | Haiku 5.5 | Sonnet 5.5 | Opus 5.5 | Fable 5.2 |
|---|---|---|---|---|
| 讀檔 | 9.4 ~ 15.7 | 10.5 ~ 19.2（重複：9.4 ~ 20.4） | 13.2 ~ 23.7 | 8.5 ~ 14.2 |
| 寫長文 | 未測 | 14.0 ~ 16.1（重複：13.5 ~ 15.0） | 18.8 ~ 24.0（修正後上限 25.0） | 9.2 ~ 12.3 |
| 反覆讀快取 | 16.1 以上（見下） | 20.9 ~ 32.1（修正後上限 41.1；重複：11.9 ~ 36.0） | 30.4 ~ 50.8 | 9.1 ~ 14.4 |

「修正後上限」是扣掉主持對話同時段用量之後的上限。Sonnet 反覆讀快取與讀檔的重複格各只夾到 1 個百分點，所以特別寬。

三件事看得出來。

**同一個模型，反覆讀快取最省。** Opus 反覆讀快取每 1% 對應 30.4 到 50.8 美元，寫長文 18.8 到 25.0，讀檔 13.2 到 23.7：前者和後兩者的範圍完全不重疊，是寫長文的 1.2 到 2.7 倍。Sonnet 第一輪也是這個型態（20.9 到 41.1 對 14.0 到 16.1），重複那一輪的範圍太寬，分不出來。白話講：API 牌價已經把快取讀取訂得很便宜，訂閱額度對它又再打了折。長時間在同一個對話裡工作、不斷重用同一份上下文，是最不傷額度的用法；一直開新對話、每次重新讀進大量檔案，或是產出大量文字，相對比較傷。（這是從不同工作型態的比較推論出來的，沒有直接拿同一個對話和新開對話對照過。）

**Fable 看不出這個優惠。** 三種工作都落在 8.5 到 14.4 之間，範圍幾乎重疊。

**寫長文這一種工作，Opus 沒有貴到牌價的 2 倍。** API 牌價上 Opus 是 Sonnet 的 2 倍。訂閱裡，Opus 寫長文每 1% 對應 18.8 到 25.0 美元，Sonnet 是 13.5 到 16.1（兩輪合起來）。換算回來，同樣的 token，Opus 扣的額度大約是 Sonnet 的 1.1 到 1.7 倍。另外兩種工作的範圍互相重疊，分不出來，所以這句話只對寫長文成立。

## 結果三：最貴的模型，比牌價差距更傷

把「做一次同樣的工作扣多少額度」算出來比較直觀。每格取子任務的中位數美元（`data/cells.csv` 的 `agent_usd_median`），除以該格的範圍。以讀一次 40 萬 token 的檔案來說：

| 模型 | 一次的 API 等值 | 扣掉的週額度 |
|---|---|---|
| Haiku 5.5 | 0.26 美元 | 約 0.02 到 0.03% |
| Sonnet 5.5 | 1.07 美元 | 約 0.05 到 0.11%（兩輪合起來） |
| Opus 5.5 | 2.15 美元 | 約 0.09 到 0.16% |
| Fable 5.2 | 4.15 美元 | 約 0.3 到 0.5% |

Haiku 的提示超過 10 萬 token 時整筆改用貴五倍的級距，上表是用那個價格算的。

Fable 和 Opus 比：

- 寫長文：牌價 Fable 是 Opus 的 2 倍，同樣的 token 在訂閱裡扣的額度是 3.0 到 5.4 倍（用 Opus 與 Fable 兩格各自的 token 組成換算，取兩者合起來最寬的範圍）。
- 反覆讀快取：兩個模型讀取快取的牌價一樣，這種工作照牌價 Fable 只貴大約一成；訂閱裡每一次小動作扣的額度卻是 Opus 的 2.4 到 6.4 倍。
- 讀檔：每個子任務 1.8 到 5.4 倍。

三種工作合起來看，是 1.8 到 6.4 倍。再加上 Fable 有自己的分項額度，上限是總額度的一半。這些倍數的算式在 `bin/compare_models.py`，可以自己重算。

## 換算成「一週值多少」

把「每 1% 多少美元」乘以 100，就是整週額度的推估。這是從前 51% 線性外推，不是實際用到 100% 量出來的，請當成量級參考。

| 如果整週都在做… | Sonnet 5.5 | Opus 5.5 |
|---|---|---|
| 讀檔型工作 | 約 1,050 到 1,920 美元 | 約 1,320 到 2,370 美元 |
| 寫長文型工作 | 約 1,400 到 1,610 美元 | 約 1,880 到 2,500 美元 |
| 反覆讀快取型工作 | 約 2,090 到 4,110 美元 | 約 3,040 到 5,080 美元 |

上表各取第一次量到的那一格，含主持對話修正後的上限。Fable 因為只能用到總額度的一半，整週全用完大約 430 到 720 美元。

實際工作是幾種的混合。我這一次的總帳是 51% 對 936 美元，照比例一週約 1,840 美元，一個月（約 4.3 週）約 7,900 美元。上表乘以 4.3，Sonnet 與 Opus 的三種工作每月約 4,500 到 21,800 美元；加上 Haiku 的讀檔（每 1% 最低 9.4 美元），下限降到約 4,000 美元。所以每月約 4,000 到 22,000 美元這個範圍，只涵蓋 Haiku、Sonnet、Opus 已經量到範圍的格子（Haiku 沒有寫長文，反覆讀快取只有下限，不在內）。Fable 只能用到總額度的一半，整個月全用完約 1,800 到 3,100 美元。

## 幾個實驗花絮

- 程式去讀官方的用量百分比，讀太勤被限速，後來改成大約兩分鐘一次才穩。
- 第一次讓 Opus 讀檔，3 分鐘就燒掉 43 美元的 API 等值，快到只抓到一次完整的跳動，夾不出範圍，那一格作廢，放慢重跑。
- 150 個 Haiku 子任務被派去讀檔，有 31 個讀的量明顯偏少，其中至少 30 個照樣回報完成。這是從帳本的 token 數抓到的。
- 叫 Haiku 用很高的推理強度（xhigh），帳本上記的卻是 low。
- 主持對話用的是最貴的 Fable，在跑 Fable 專門測試之前，光是主持就吃掉大約 3.5% 的週額度。
- 最後一格（Haiku 反覆讀快取）跑到一半，主持對話回覆了一則訊息。光是醒來、重建快取、查進度，第一分鐘就用掉約 1.9 美元的 API 等值；它接著做手上排著的工作，到那一格結束為止整輪共約 9 美元，約是週額度的 0.6% 到 1.1%，剛好混進正在量的那一格。所以那一格只剩下限（每 1% 至少 16.1 美元），要重跑才有上限。

## 這些數字的限制

- **讀數只有整數。** 每一格只夾到 1 到 3.5 個百分點，範圍寬。
- **只有一個帳號、一個方案、同一個每週額度視窗（2026-11-17 15:50 到 11-18 01:45，台灣時間，約 10 小時），量到 51%。** 規則隨時可能改，換一個方案也可能不同。
- **提示都很長。** 讀檔與反覆讀快取的上下文約 40 萬 token，寫長文約 20 多萬到 30 多萬，短對話是否同樣比例還沒測。
- **Haiku 只量到一半。** 寫長文沒測，反覆讀快取只有下限。
- **有少量用量對不上。** 即使讓每個模型的每一類 token 各有一個換算，在預設的時間容許值下，全部讀數仍差 0.21 到 0.39 個百分點（三種取整方式）。可能是沒寫進紀錄檔的背景小呼叫，也可能是讀數延遲。
- **讀數怎麼取整、起跑真值是多少都不知道。** 分析把它們當未知數；跨格的範圍用的是兩次跳動之間的差，不受取整方式影響。
- **「API 等值」不是實付。** 我沒有真的走 API 付這些錢，是用牌價算的。
- **整週與整月的數字是外推。** 沒人說得準後半段扣得一樣快。

## 可以帶走的四件事

1. 同一件事留在同一個對話裡做完。重複利用同一份上下文最省額度（Fable 除外）。這是推論，不是直接對照出來的。
2. 需要好一點的模型就用 Opus。寫長文時它在訂閱裡沒有扣到牌價的 2 倍。
3. 最貴的模型省著用。同樣的工作它扣的額度是 Opus 的 1.8 到 6.4 倍，而且只有一半的額度可以給它。
4. 雜事交給最小的模型。讀一次 40 萬 token 的檔，Haiku 只扣大約 0.02 到 0.03%。

## 想自己驗證

程式、原始資料和完整流程都在這個庫裡。

- 沒有訂閱帳號：可以用庫裡的資料重跑全部分析，檢查每一個數字是怎麼來的。
- 有訂閱帳號：照 `PROTOCOL.md` 用自己的資料夾重做整個實驗。讀數可以手動抄，不需要碰任何登入憑證。
- 程式只在 macOS 上驗證過：產生測試檔的 `bin/make_corpus.py` 讀 macOS 的系統字典 `/usr/share/dict/words`，圖表字型也是 macOS 的字型。

如果你量出來的數字不一樣，那比一樣更有價值。
