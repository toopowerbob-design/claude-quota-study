# 已知限制

這份資料只能支持 README 裡列的結論。下面是沒有修、或修不了的限制，引用數字前請先讀。

名詞：**主持對話**是發動並記錄這次實驗的那個 Claude Code 對話，用的是 Fable 5.2；它自己的用量也會扣額度。

- **讀數只有整數。** 每一格實驗只夾到 1 到 3.5 個百分點，範圍寬；只夾到 1 個百分點的格更寬。
- **只有一個帳號、一個方案、同一個每週額度視窗（2026-11-17 15:50 到 2026-11-18 01:45，台灣時間，約 10 小時），量到 51%。** 方案是每月 200 美元的方案（介面顯示為 Ultra，即原本的 Max 20x）。整週與整月的美元數都是線性外推，不是量到的。計量規則隨時可能改。
- **只在 macOS 上驗證過。** `bin/make_corpus.py` 讀 macOS 的系統字典 `/usr/share/dict/words`，圖表字型也是 macOS 的字型；其他系統沒有試過。
- **Haiku 只量到一半。** 反覆讀快取那一格被主持對話的用量干擾，只有下限；寫長文沒有測（它太便宜，要量出 1% 得跑好幾個小時）。
- **Haiku 讀檔那一格，150 個子任務裡有 31 個讀得明顯偏少**（用量低於中位數的 80%）。所以跨模型比較讀檔時，用的是子任務的中位數，不是平均。
- **Haiku 的推理強度沒有控制住。** 子任務要求的是 xhigh，帳本記的是 low，所以推理強度不是受控變數。
- **Fable 讀檔那一格（`f1-fable-digest`）與不相干的 Sonnet、Opus 工作同時進行。** 背景有 AI 審查員在審這個庫（審查紀錄沒有放進這個庫）與一個文字工作，格內其他模型的用量合計 7.08 美元。這一格的範圍只靠 Fable 分項讀數，並假設其他模型的用量不會算進這個分項。
- **上下文都很長。** 讀檔與反覆讀快取約 40 萬 token，寫長文約 20 多萬到 30 多萬。短對話沒有測。
- **「同一件事留在同一個對話裡做最省」是推論。** 這是從不同工作型態的比較推論出來的：實驗量的是三種工作型態（一次讀進大量檔案、寫長文、反覆讀同一份快取），沒有直接拿同一份工作比較「一個對話做完」與「分成多個新對話做」。
- **讀數怎麼取整、起跑真值是多少都不知道。** 分析把這兩件事當未知數處理，三種取整方式各算一次。
- **有少量用量對不上。** 即使用最寬鬆的假設，在預設的時間容許值下仍差 0.21 到 0.39 個百分點（三種取整方式），可能是沒寫進紀錄檔的背景小呼叫或讀數延遲。
- **「API 等值」是牌價乘 token 數。** 沒有實際走 API 付款對照。
- **資料裡沒有起跑那一刻的讀數。** 讀數檔的第一筆是 2026-11-17 15:50:48（台灣時間）：每週總額度 0%，每週 Fable 分項已經是 1（1 點等於總額度的 0.5%）。帳本從 15:44 起算，所以 15:44 到 15:50 之間沒有任何讀數。事件紀錄第一筆（`baseline`）的備註寫到開始前約 15:40 介面上兩個讀數皆 0%，以及 15:46:40 的一筆程式讀數（總額度 0、Fable 1），這兩筆只有備註裡的文字，沒有進讀數檔，無從核對。所以分析把兩個讀數起跑時的真值當未知數（見 [PROTOCOL.md](../PROTOCOL.md) 第 8 節）。
- **用量全部來自 Claude 桌面版裡的 Claude Code。** 子任務由流程腳本在同一個應用程式裡發動，沒有用非互動的 `claude -p`。別人的資料顯示，用量從哪個入口來、是不是互動使用，扣法可能不同（見 [RELATED_WORK.md](RELATED_WORK.md)），這裡的數字不一定適用其他用法。
- **快取讀取的換算是反推的範圍，不是單獨量到的。** `bin/cache_weight_bounds.py` 用混合比例不同的格子，反推「一美元牌價的快取讀取扣的額度」是「一美元牌價的快取寫入」的幾倍（1 表示照牌價算，小於 1 表示快取讀取算得比牌價便宜）：Opus 0.16 到 0.73，Sonnet 0.19 到 0.89，Fable 0.43 到 1.98（跨過 1，分不出比牌價便宜還是貴），Haiku 夾不出上限。換成每個 token，Opus 重讀一個快取 token 約扣第一次寫入快取（5 分鐘）一個 token 的 1/34 到 1/160（牌價是 1/25），Sonnet 是 1/28 到 1/135（牌價 1/25），Fable 是 1/25 到 1/115（牌價 1/50）。這只能和 5 分鐘的快取寫入比：每一格幾乎沒有一般輸入，主持對話的 1 小時快取寫入也沒有另外量。Sonnet 的結果靠第一輪，單看第二輪分不出來。時間容許放到很寬（300 秒）時，Opus 的上限會超過 1，所以「比牌價便宜」只在預設設定下成立。
- **快取寫入幾乎都是 5 分鐘那一種。** 1 小時快取寫入在額度上照哪個價算，這份資料回答不了。
- **主持對話的修正是保守估計。** 用的是受控 Fable 格裡最小的換算下限，不是量出來的值。
- **公開版的資料做過去識別。** 帳本拿掉了訊息代號、請求代號與來源檔名，對話與子任務代號換成流水號；官方用量回應的原始內容沒有放進來，只留讀數。分析結果與原始資料算出來的相同。
